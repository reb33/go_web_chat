# Требования и спецификация MVP: Веб-чат на Go

Документ описывает минимальный набор функционала (MVP) для веб-чата, разрабатываемого в рамках изучения Go, Echo, HTMX, Tailwind, WebSockets и pgxpool.

---

## 1. Общее описание
Система представляет собой простой веб-чат с возможностью авторизации по простому логину (без паролей на этапе MVP), создания комнат (групп) и обмена сообщениями в реальном времени.

---

## 2. Роли и пользователи
В системе нет разделения на роли (админ/модератор) на первом этапе. 
* **Пользователь**: идентифицируется уникальным логином (`username`).

---

## 3. Пользовательские сценарии (User Stories)

### Сценарий 1: Авторизация (Вход на сайт)
1. Пользователь открывает главную страницу сайта (`/`).
2. Если пользователь не авторизован, он видит форму ввода логина.
3. Пользователь вводит свой логин (например, `alex`) и нажимает кнопку «Войти».
4. Система проверяет, существует ли такой пользователь в БД:
   - Если существует — авторизует его (например, сохраняет сессию / куку / ID в контексте).
   - Если не существует — создает нового пользователя в БД и авторизует.
5. После успешного входа пользователь перенаправляется на страницу со списком групп (`/chats`).

### Сценарий 2: Просмотр списка групп и создание новой
1. Авторизованный пользователь видит список доступных чат-групп.
2. Пользователь видит форму «Создать новую группу».
3. Пользователь вводит название группы (например, `Go Lang Rust`) и нажимает «Создать».
4. Система создает группу в БД, автоматически связывает создателя с этой группой (добавляет в участников) и обновляет список групп на экране (с помощью HTMX).

### Сценарий 3: Подключение к группе (чату)
1. Пользователь в списке групп видит те группы, в которых он состоит, или может зайти в общий каталог и подключиться (`Join`) к любой существующей группе.
2. При клике на группу пользователь переходит на страницу конкретного чата (`/chats/{group_id}`).
3. Система проверяет, является ли пользователь участником группы:
   - Если нет — автоматически добавляет его в участники (или показывает кнопку «Вступить»).
   - Если да — открывает интерфейс чата (история сообщений + окно ввода + WebSocket соединение).

### Сценарий 4: Отправка и получение сообщений (WebSocket + HTMX)
1. Находясь на странице чата (`/chats/{group_id}`), пользователь видит историю последних сообщений.
2. Пользователь вводит текст в поле ввода и нажимает Enter (или кнопку «Отправить»).
3. Сообщение отправляется на сервер через WebSocket (или через HTMX form POST с последующим рассылаем в WS).
4. Сервер сохраняет сообщение в базу данных (`messages`).
5. Сервер рассылает новое сообщение (отрендеренный HTML-фрагмент) всем активным участникам, находящимся в этой же группе через WebSocket.
6. У всех участников мгновенно обновляется лента чата без перезагрузки страницы.

---

## 4. Нефункциональные требования (для архитектуры)
1. **База данных:** PostgreSQL, работа через `pgx/v5/pgxpool` без ORM (чистый SQL).
2. **Миграции:** Liquibase (XML/YAML changelogs).
3. **Фронтенд:** HTML-шаблоны рендерятся на бэкенде (Echo), динамика за счет HTMX и Tailwind CSS.
4. **Реальное время:** WebSockets для чата.
